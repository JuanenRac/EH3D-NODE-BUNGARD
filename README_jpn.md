# 📡 EH3D-NODE-BUNGARD

**正直さの確認 - 今日実際に動くもの：** ESP32-S3（ESP-IDF 5.5）向けの C++17 ファームウェアで、Bungard CCD 機械の制御ユニットの RS-232 ポートをネットワーク ポートにします。プログラムがアクセス トークン付きで TCP 接続し、機械をアームして動きのバイト列を送ると、ノードはそれをキューに入れ、回線自身のペースで送り出します。機械のランプ（HOME X・Y・Z、ENABLE、TOOL）を読み、0〜10 V の速度信号と運転／方向ラインでスピンドルを制御し、セットアップ、ユーザー、ネットワーク、更新、機械固有の設定のための、サイド メニュー付き Web パネル（37 言語）を備えます。リンクの規則と設定はコンピューター上でテスト済み（テスト プログラム 10 本、数えられた検査 2,235 件）で、ファームウェアは両方の基板で警告なしにビルドできます。**基板への書き込みも実行もまだ行っておらず**、機械にも何も接続しておらず、RS-232 変換、ランプ入力、スピンドル ドライブをまとめるキャリア基板は紙の上の設計です。

---

> **安全性とセキュリティの現状：** これは安全装置ではありません。配線の誤ったノードや、設定の誤ったスピンドル ドライブは、機械を動かしたり工具を回したりする可能性があります。ノードはアクセス トークンなしでは制御を受け付けず、プログラムがアームしている間だけ機械用のバイトを受け取り、セッションが途絶えるか接続が切れると停止します（キューを空にし、ステッピング ドライバーとスピンドルを切ります。保持中のジョブを終わらせる任意設定がオンの場合を除く）。機械のリミット スイッチはランプ越しにしか見えず、独自の非常停止もまだありません（キャリア基板には押しボタン入力の場所があります）。スピンドルのドライブは商用電源電圧なので、メーカーのマニュアルに従って配線・設定してください。パネルは機械を動かすことはなく、プログラムが機械をアームしている間は設定の保存を拒否します。このプロジェクトは独立しており、Bungard Elektronik による製造・承認・サポートではなく、製品名は対象とする機械とドライブを示すためだけに使っています。

## 🎯 概要

* **制御リンク**（TCP、既定のポートは 5800）：CRC 付きのフレーム化プロトコル、アクセス トークンによるログイン、アーミング、制御ユニット用のバイト キュー、セッションが途絶えるか切れたときの停止。プログラムは間隔を付けた動きのバイト列を送り、ノードの UART がそれを正確に回線へ出します。USB シリアル アダプターには高速でこれができません。
* **制御ユニットへのシリアル回線**：MAX3232 経由の 38400 ボー 8N1 と、ハンドシェイクの DTR、DCD、RI ライン。ピンと、トランシーバーがラインを反転するかどうかは設定です。
* **ランプ**：HOME X、HOME Y、HOME Z、ENABLE、TOOL をバッファー トランジスタ経由で読み、ステータスとパネルに表示します。リクエストにより、軸が原点に着いた瞬間にノードが残りの探索を破棄できるため、プログラムはストリームの途中で原点ラインを読む必要がなくなります。
* **スピンドル**：0〜10 V コンバーター用の速度 PWM（既定では信号最大で 24000 rpm、Huanyang HY02D223B のようなインバーター向け）と正転／逆転ライン。回転中や停止直後の方向変更はせず、機械が停止するたびに停止します。
* **パネル**（HTTP と HTTPS、37 言語、広い画面では左、スマートフォンでは上にメニュー）：USB コンソールに表示されるコードによる初回セットアップ、ユーザー、Ethernet または Wi-Fi、制御リンク、RS-232 ピン、ランプとスピンドル、ログ、2 つのファームウェア スロットの一方へアップロードしてロールバックできる更新。秘密情報はイメージに組み込まれません。
* **自己保護**：タスクとメモリを監視するガード、メモリ不足時のパネル入口のゲート、ノードに到達できるようになった時点での新しいイメージの確認。
* **基板**：Waveshare ESP32-S3-ETH（W5500 Ethernet）と ESP32-S3-WROOM-1 N16R8（Wi-Fi）で、それぞれ専用のイメージがあります。キャリア基板（100 x 100 mm）の設計は `docs/BOARD.md` にあります。
* **機械**：DOS ソフト 4.6 のシリアル ポート制御ユニットを持つ Bungard CCD MTC と CCD/2 MTC。ATC の 2 モデルは対象外で、XL モデルとそれ以降の機械は独自の最新の制御ユニットを持ちます。
* **自律的な終了**（既定ではオフ、設定）：プログラムまたはサーバーがいなくなると、ノードはキューにすでにあるバイト（キューに入ったスピンドル コマンドを含む）を最後まで実行し、スピンドルとドライバーを切ります。キューは外部 RAM に置かれ（最大 4 MB、数分の動き）、時間制限、Abort、パネルの停止ボタンで終了します。**計画中でまだ作っていないもの**：物理停止用の押しボタン入力。

## 🧩 EH3D での役割

EH3D-NODE-BUNGARD は、EH3D のプログラムと機械のあいだの最終段です。現在は EH3D-DRILLPRO と EH3D-ROUTEPRO が接続し、他のクライアントのためには EH3D-SERVER がその前に立ちます。EH3D ファミリー最初のノードで、設定、パネル、更新の仕組みは、後に続くノードと共有する前提です（共通の基盤は EH3D-COMMON にあります）。

## ✨ 機能

* **サイド メニュー付きパネル：** 7 ページ（ステータス、機械、ネットワーク、ユーザー、ファームウェア、ログ、システム）。広い画面ではメニューが左、スマートフォンでは上にあり、言語、テーマ、サインアウトが隣にあります。
* **イメージは 1 つ、秘密なし：** ノードごとに違うものはすべて、パネルで編集するフラッシュ上の設定ドキュメント 1 つです。パスワード、トークン、ネットワークはビルドに含まれません。
* **正しいタイミングのバイト：** プログラムが各ステップを配置し、ノードの UART が回線自身のペースで送ります。USB アダプターには維持できません。
* **原点をライブで確認：** 5 つのランプを読み、軸が原点に着いた瞬間にリクエストで探索の残りを破棄できます。
* **ガードレール付きスピンドル：** ノードが想定する最高速度で制限し、回転中や停止直後は逆転せず、機械とともに停止します。
* **ロールバック付き更新：** イメージは動いていないスロットに入り、ノードに到達できるまで試用中です。到達できなければブートローダーが元へ戻します。
* **自己管理：** ガードがタスクとメモリを監視し、90 秒たってもアドレスのないノードはセットアップ ネットワークを再び開いて、到達不能のまま残らないようにします。
* **A.R.M.O.R. のノードと同じノードのパネル：** グループ化されたメニュー（ノード、ネットワーク、システム）と、下部の言語選択とサインアウト。概要（ノード、ハードウェア、時計、フラッシュ、ネットワーク）、メインのネットワークが失われたときにノードが試す最大 3 つの予備ネットワークを持つ Wi-Fi ページ、完全なヘルプとバージョン情報のページ、そしてファームウェアでは GitHub からの更新（プロジェクトの最新リリースを探し、SHA-256 を確認し、もう一方のスロットにインストール）、2 つのスロットの切り替え、実行中のものをもう一方へコピーする機能。
* **37 言語：** ノードの Web パネルが対応する言語：英語、スペイン語、イタリア語、ドイツ語、フランス語、ポルトガル語、中国語、日本語、ブルガリア語、クロアチア語、チェコ語、デンマーク語、オランダ語、エストニア語、フィンランド語、ギリシャ語、ハンガリー語、アイルランド語、ラトビア語、リトアニア語、マルタ語、ポーランド語、ルーマニア語、スロバキア語、スロベニア語、スウェーデン語、ノルウェー語、アイスランド語、ウクライナ語、ロシア語、セルビア語、アルバニア語、カタルーニャ語、ガリシア語、バスク語、ブラジルのポルトガル語、カナダのフランス語。 最初の 8 言語以外の 29 言語はモデルによる翻訳で、ネイティブによる確認待ちです。ない文言は英語で表示されます。

## 🔒 セキュリティと安全

| 脅威 | 防御 |
|---|---|
| ネットワーク上の誰かが機械を動かす | アクセス トークン（印字可能な 8〜64 文字）が正しくなるまで、リンクは Hello 以外をすべて拒否します。トークンのないノードは、ベンチ用設定 `allow_open`（既定はオフ）がオンでない限り制御を拒否します。同時に 1 つのプログラムだけ |
| 誤って機械を動かすプログラム | バイトはアーム中にのみ、フレーム全体がキューに収まる場合にのみ受け付けます。スピンドル コマンドは最高速度に制限され、回転中のスピンドルを反転させる場合は拒否されます |
| 外れたケーブル、または動きの途中で止まるプログラム | アーム中のセッションが `idle_ms`（既定 3000 ms）のあいだ無言、または接続が切れると、キューを空にしてドライバー オフのバイト `0xC0` を送り、スピンドルは 0 rpm になります |
| パネルへの到達 | 最初の管理者は USB コンソールにだけ表示されるセットアップ コードで作成します。権限は 2 種類（管理者、閲覧者）。誤ったパスワードは遅延され、失敗し続ける送信元アドレスは一定時間ブロックされます。HTTP、HTTPS、または両方 |
| ファームウェアやリポジトリ内の秘密情報 | 秘密情報はビルドに含まれません。トークン、ネットワーク、ピンはフラッシュ上の設定で、トークンはパネルと API では書き込み専用です |
| 動きを止めてしまう設定の書き込み | プログラムが機械をアームしている間、パネルは設定の保存を拒否し（HTTP 409 `machine_armed`）、再起動を延期します |
| ピン割り当ての誤り | 基板が予約しているピン（フラッシュ、PSRAM、USB、Ethernet チップ）は拒否され、1 つのピンに 2 つの役割は割り当てられません |
| 不正なファームウェア イメージ | 別のプロジェクトのイメージや空のスロットは拒否されます。新しいイメージは試用中で、パネルが起動しない、または 5 分以内にノードへ到達できない場合、ブートローダーは前のイメージに戻します |
| メモリ不足やハングしたノード | ガードがタスクと内部メモリを監視し、ループを作らずに再起動します。メモリ不足時はパネル入口にゲートがあります |
| ノードを手にした人 | 電源投入後の最初の 30 秒に BOOT を 8 秒押し続けると、設定とユーザーが消去されます（物理アクセスはリセットという設計） |

**防御していないこと：** ノードにはまだ非常停止入力がなく、リミット スイッチはランプ越しにしか見えません。更新には署名がありません（GitHub からの更新は、リリースが公開する SHA-256 を HTTPS で確認し、管理者が求めたときだけ動きます。署名鍵はまだありません）。HTTPS パネルの自己生成証明書のため、ブラウザーは警告を出します。基板では何も動かしておらず、独立したレビューも受けていません。脆弱性は非公開で報告してください（[SECURITY.md](SECURITY.md) 参照）。

| USB コンソール | セットアップ コードを表示し、シリアル経由の Improv Wi-Fi を受け付けます | `main/improv_serial.cpp` |
| セットアップ ネットワーク | ユーザーがいない間、ノードは Wi-Fi `EH3D-SETUP-xxxxxx` を開きます | [docs/NODE_FIRMWARE.md](docs/NODE_FIRMWARE.md) |

## ⚙️ 設定

すべてはフラッシュ上の設定で、パネル（機械ページ）から編集するため、1 つのイメージですべてのノードをまかなえます。以下は一度も設定されていないノードの値で、範囲外の値は保存時に拒否されます。

| 設定 | 既定値 | 範囲 | 内容 |
|---|---|---|---|
| `machine.link.port` | 5800 | 1024 〜 65535 | 制御リンクの TCP ポート |
| `machine.link.token` | なし | 印字可能な 8〜64 文字、書き込み専用 | アクセス トークン。ないとノードは制御を拒否します |
| `machine.link.allow_open` | オフ | オンまたはオフ | ベンチ用の設定：トークンなしで制御を受け付けます |
| `machine.link.idle_ms` | 3000 | 200 〜 60000 | アーム中のセッションが無言でいられる時間。超えるとノードが停止します |
| `machine.link.queue_bytes` | 262144 | 1024 〜 4194304 | 制御ユニット用のバイト キュー（外部 RAM 上） |
| `machine.link.finish_on_loss` | オフ | オンまたはオフ | プログラムがいなくなったとき、キューにあるジョブを終わらせます |
| `machine.link.max_drain_s` | 600 | 10 〜 3600 | その場合にノードが単独で続けられる最大秒数 |
| `machine.uart.*` | tx 17、rx 18、dtr 15、dcd 16、ri 21、cts と dsr は未接続、トランシーバーは反転 | 基板の空きピン、任意項目は -1 | シリアル回線のピン |
| `machine.lamps.*` | HOME X 1、Y 2、Z 7、ENABLE 8、TOOL 38、アクティブ ロー | 空きピン | 5 つのランプ入力 |
| `machine.spindle.max_rpm` | 24000 | 0 〜 65535（0：スピンドル出力なし） | 信号最大時の速度 |
| `machine.spindle.pwm_hz` | 2000 | 100 〜 40000 | 速度信号の周波数 |
| `machine.spindle.reverse_delay_ms` | 3000 | 0 〜 60000 | 逆方向に回せるようになるまでスピンドルが停止していなければならない時間 |
| `web.mode` | `both` | `http`、`both`、`https` | パネルをポート 80、443、または両方で配信するか |

スピンドルのピン（PWM 4、正転 5、逆転 6）も設定です。すべてのノードが持つ設定（名前、接続方法、アクセス ポイント、アドレス、時計、言語、定期再起動）は基盤にあり、[docs/NODE_FIRMWARE.md](docs/NODE_FIRMWARE.md) に説明があります。

## 🚀 クイックスタート

ホスト テストには C++17 コンパイラーと CMake、ファームウェアには ESP-IDF 5.5（または Docker）が必要です。

```bash
build.bat            # the host tests (Windows)  -  ./build.sh on Linux
tools/build_node.sh s3-eth      # or s3-wifi: the firmware, in the ESP-IDF container
python -I tools/ci_validate.py
```

`tools/build_node.sh s3-eth`（または `s3-wifi`）は ESP-IDF コンテナーでイメージをビルドします。Windows ではインストール済みの ESP-IDF 5.5.5 でも同様にできます。イメージ `dist/eh3d-node-bungard-<バージョン>-<基板>-complete.bin` は 1 種類の基板専用です。`python -m esptool --chip esp32s3 -p COMx write_flash 0x0 <イメージ>` でアドレス 0 に書き込みます。次に、ノードが開く Wi-Fi `EH3D-SETUP-xxxxxx` に接続し、`http://192.168.4.1/` を開いて、USB コンソールに表示されるセットアップ コードを入力します。アクセス トークン、ネットワーク、ピンはパネルで設定します。この手順はまだ実際の基板では行っていません。

## 🧪 テスト

ホスト テスト（`build.bat` または `./build.sh` のあと `ctest`）は 10 本のプログラムで、すべて通ります。`core_tests`（104 件：フレームとセッション規則）、`test_base`（382）、`test_clock`（ok を出力）、`test_settings`（392）、`test_machine`（75）、`test_shared`（627）、`test_shared_eth`（629、Ethernet 基板プロファイル）で数えられた検査は 2,235 件、さらに `panel_text`（37 言語 315 行、使用キー 265、文言のあるファームウェア エラー コード 36）と `task_safety`（10 タスク、小さなスタックに設定の大きなコピーを置かない）です。CRC と破損後に再同期するデコーダー、トークン ログイン、アーミング、無言時の停止、スピンドルの規則（上限、反転禁止、遅延）、設定とその範囲、ピンの競合と予約ピン、ユーザーとセッション、ネットワーク計画、時計、JSON を網羅します。パネルは、基板なしで配信する代替ノード `tools/panel_mock.mjs` に対してブラウザーでも動作確認しています。CI は `python -I tools/ci_validate.py` と、警告をエラーとして Linux 上でホスト テストを実行します。2 つのファームウェア イメージのビルド（ESP-IDF 5.5.5）は手作業で、CI には含まれません。基板上では何も動いていません。

## 🏗️ ビルドとリリース

バージョンは `eh3d.project.json` とビルドにあり、各バージョンには [CHANGELOG.md](CHANGELOG.md) の項目があります。`build.sh` / `build.bat` はホスト テストをビルドして実行し、`test.sh` / `test.bat` はテストだけを実行します。いずれもライブ パネルで動き、バージョンは変えません。ファームウェア イメージは `tools/build_node.sh`（Windows では ESP-IDF 5.5.5）で作られ、`eh3d-node-bungard-<バージョン>-<基板>-{app,complete}.bin` という名前になります。リリースはまだ公開しておらず、イメージを書き込んだこともありません。GitHub からの更新は実装済みですが、基板で本物の GitHub に対して動かしたことはありません。リリースは署名されておらず、公開されているハッシュを信頼します。

## 🩺 トラブルシューティング

| 症状 | 対処 |
|---|---|
| ノードに到達できない | 90 秒たってもアドレスのないノードはセットアップ ネットワーク `EH3D-SETUP-xxxxxx` を再び開きます。それに接続し、パネルで接続方法を設定してください。 |
| セットアップ コードをなくした | USB コンソールにだけ、15 秒ごとに表示されます。電源投入後の最初の 30 秒に BOOT を 8 秒押し続けると、設定とユーザーが消去され、セットアップが最初からやり直しになります。 |
| リンクが Error 1 または 2 を返す | ログインしていない、またはトークンが違います。最初のフレームは、パネル（機械ページ）で設定したアクセス トークン付きの Hello でなければなりません。 |
| Error 3 または 4 | アームされていない（先に Arm を送る）、またはキューが満杯です（Status に空きが出るまで待つ）。 |
| Error 7 | アーム中のセッションが `idle_ms` のあいだ無言でした。長い動きをキューに入れている間は Ping を送ってください。 |
| Error 9、10、11 | 反転する前にスピンドルを止める必要がある、反転するには停止から時間が短すぎる、またはノードが保持中のジョブを終わらせている最中です。 |
| パネルが保存を拒否する（409 `machine_armed`） | プログラムが機械をアームしています。解除するか、ステータス ページの停止ボタンを押してから、もう一度保存してください。 |
| ブラウザーが HTTPS パネルについて警告する | ノードは初回に自前の証明書を作ります。信頼できるネットワークでは `http` または `both` モードを使うか、証明書を受け入れてください。 |

## 🗺️ ロードマップと既知の制限

**現時点で分かっている制限**

* 基板では何も動いていません。イメージの書き込み、実際のノードでのセットアップ、プログラムとの通信、機械への接続はまだありません。
* RS-232 変換、ランプ入力、スピンドル ドライブを備えたキャリア基板は紙の上の設計です（`docs/BOARD.md`）。
* ノードには非常停止入力がなく（キャリア基板には押しボタン用の場所があります）、リミット スイッチはランプ越しにしか見えません。
* GitHub からの更新は実装済みですが、基板で本物の GitHub に対して動かしたことはありません。リリースは署名されておらず、公開されているハッシュを信頼します。パネルは代替ノードに対してブラウザーで確認しただけで、基板から配信したことはありません。
* 保持中のジョブを終わらせる動作は基板では動いておらず、その規則はコンピューター上でテスト済みです。
* 対象は Bungard CCD MTC と CCD/2 MTC のみで、ATC モデルは対象外です。

**次のステップ**

* 各基板にイメージを書き込み、最初のセットアップを行い、Rust ライブラリとのリンクを確認する。
* キャリア基板を設計・製作し、スピンドル ドライブと機械を接続する。
* 物理停止用の押しボタン入力を追加する。
* リリースに署名し、GitHub からの更新で署名を確認する。
