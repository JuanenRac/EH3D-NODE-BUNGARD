# Changelog

## [Unreleased]
- **A watchdog for the manual build:** `.github/workflows/build-watchdog.yml` looks every hour for a build that stays queued or running longer than the limit in `.github/build-watchdog.json` and opens (or updates) an issue `build-stuck`, which it closes when no build is stuck.
- **Firmware builds in GitHub Actions:** `.github/workflows/firmware-build.yml` (manual, owner only) builds the images in the pinned ESP-IDF container, writes `SHA256SUMS`, a build manifest and a provenance attestation, checks the version inside every image, opens an issue `build-failed` when it fails and prepares an unsigned draft release only after the owner approves it; the signature stays on the maintainer's computer. See `docs/NODE_FIRMWARE.md`.
- **Shared checks updated:** the validator also compares the badge and the Version row of the README with the manifest, fails when one of its checks cannot run, and the CHANGELOG step of the workflow reads the base branch from the environment.

- **A self-test for the day the node meets the hardware:** `tools/selftest.py` reads the node through its panel API and the control link (version, state, settings, the settings export compared with itself and never applied, backup networks, OTA state, spindle state, link idle state) and writes `selftest_bungard_<time>.txt` with one line per step. With `--active` and a typed confirmation (or `--yes`) it arms the link, turns the spindle by the queue, and times the Abort and the panel's stop; every active step ends with the spindle stopped and the link disarmed, and the end of the run checks it with a new connection. Nothing is written to the node without `--active`; the token and the password are never printed. Its tests run against a toy node in the CI.
- **`docs/HARDWARE_CHECKLIST.md`:** the steps to do by hand on the bench, with what must happen and where to write the result.
- **More host tests:** the queue of bytes, versions, node names, the retries of a send, the addresses the web server answers and the frames of the control link read from a noisy line.
- **The workflows are hardened:** every action is pinned by its commit with its version in a comment, and the checkouts keep no credentials.

## [0.0.5] - A save bar that is always there, a backup of the settings and a stop that stops the spindle on every path

- **A stop always switches the spindle off at the hardware:** Abort, Disarm, a silent link, the home stop and the panel's stop send the order to switch the spindle off whatever the session believes about it, instead of only when its copy of the state says it turns. A new test models the spindle (a command in the queue takes effect when the bytes before it have gone out, a flush drops what has not gone) and runs thousands of random sequences: after any stop the spindle is off and nothing in the queue can start it.
- **A button to copy the access token** next to the one that is generated (and next to a typed one), also over plain HTTP, where the clipboard of the browser is not there; the text says whether it was copied.
- **The panel in 37 languages:** Bulgarian, Croatian, Czech, Danish, Dutch, Estonian, Finnish, Greek, Hungarian, Irish, Latvian, Lithuanian, Maltese, Polish, Romanian, Slovak, Slovenian, Swedish, Norwegian, Icelandic, Ukrainian, Russian, Serbian, Albanian, Catalan, Galician, Basque, Brazilian Portuguese and Canadian French join the first eight. The words of the new ones are in `panel/locales/CODE.tsv` and are packed into one file, `/langs.js`, that the browser asks for only when one of them is chosen (about 250 KB packed; the panel of the first eight languages is as light as before); a text that a language does not have is shown in English, or in Portuguese or French for the two variants. The node accepts the new codes in `ui.language`. `tests/check_panel_text.py` checks the files (known keys, placeholders, all the texts, the size). The translations are the work of the model and wait for a review by native speakers.
- **A send to the program never waits for ever:** the loop of the link gives a send one second (`core/send_loop.hpp`, tested with a stand-in socket), then drops the connection like any lost link; the socket also has a send timeout of 200 ms and keep-alive probes, so a cable that is cut is noticed and the idle timeout, the drain and the stop button of the panel keep running.
- **The documented overrun after a stop is the real one:** up to 128 bytes (about 33 ms at 38400 baud) already in the transmit FIFO of the chip still go out before the `0xC0`.
- **A save bar that is always there:** Save and Save and restart show on every page with settings (off, with a note, until something changes) and Restart is always at hand for an administrator; before, the buttons appeared only after a change and the whole bar was hidden otherwise.
- **Backup of the settings from the panel:** the System page exports every setting to a `.json` file (it holds the Wi-Fi passwords and the token) and imports one back into the forms without sending anything, so each page is saved with its own Save; the id, name and host name of the node are never changed by an import.
- **The backup Wi-Fi networks are saved:** `networkBody()` did not carry `sta.backup`, so adding or removing one showed no change and was never sent. The fields the network pages send are now one list (`NETWORK_FIELDS`) and `tests/check_panel_text.py` fails when a page paints a field that is not in it (or the machine body lacks one it paints).
- **More of the node's settings in the panel:** the Network page edits the name of the node, the time server and its use, the time zone and the periodic restart (the firmware already had them).
- **Texts:** thirteen new texts in the 37 languages. Written for the browser and tried only on a computer, not on a board.

## [0.0.4] - A panel like the ARMOR nodes have it, and the update from GitHub

- **The panel of the node as the nodes of A.R.M.O.R. have it:** the menu in groups with the language and the sign-out at its foot, the Summary, the Wi-Fi page with up to three backup networks, the complete Help and the About page.
- **The update from GitHub and the copy of a slot:** the node looks for the newest release of its project, checks the SHA-256 that the release publishes, installs it in the other slot and restarts (an administrator asks for each step); `core/release_assets.hpp` picks the image of the board and refuses any address that is not a file of the repository's own releases; the running firmware can be copied into the other slot. The releases are not signed yet.
- **Tests:** `test_release` (26 checks: the addresses that may be downloaded from, the image of each board and of each node of the family, the versions).

- **The panel in the look of EH3D-BUNGARD-GUI and EH3D-STUDIO:** the Forge theme by default (warm black, amber, cards with two cut corners) and Paper as the light theme; the pictures of the README are taken again with it, six pages, by `tools/panel_shots.mjs` against the stand-in node.
## [0.0.3] - A left menu for the web panel and the live panel of the scripts

- **Security policy and support page of the node:** they described a file reader; they now describe the control link, the panel, what is tested and what is not.
- **README in the universal layout, in eight languages:** the README has the same sections in the same order as the other repositories of the family (status, overview, architecture, features, security, interfaces, configuration, quick start, testing, structure, roadmap and known limits), with figures taken from the code and from the tests that were run. The Architecture and Repository Structure pictures are drawn from `docs/architecture.json` and `docs/structure.json` by `tools/make_architecture.py` and `tools/make_structure.py`, and the CI checks that they match.

- **The panel has its menu on the left, like the panels of the ARMOR nodes:** on a wide screen the pages are a column on the left (with an icon each), the brand, the language, the theme and the sign-out above them; on a narrow screen, a phone, the menu goes on top as a row that slides sideways. The Machine page keeps the parameters of the Bungard machine (control link, RS-232 unit, lamps and spindle).

## [0.0.2] - Settings, web panel, update with rollback, stop button and finishing the held job

- **Settings and panel:** everything that differs from one node to another is one settings document in flash, edited from the node's web panel (HTTP and HTTPS, eight languages): the first-run set-up with a code shown on the USB console, users and login, Wi-Fi or Ethernet, the control link (port, access token, idle time, queue), the RS-232 pins, the lamps and the spindle. No password, network or token is compiled into the image. Updates by upload from the panel into one of two firmware slots, with rollback and a switch between the slots; a log; a restart and a factory reset. While a machine is armed the panel refuses to save, so a write to flash cannot cut a move.
- **Finishing the job it holds:** with the setting `finish_on_loss` (off by default), when the program or the server goes away the node runs the bytes already in its queue to the end, with the spindle commands queued among them, then switches the spindle and the drivers off. The queue lives in the external RAM (up to 4 MB), a time limit and an Abort end it, and the panel has a stop button that works with or without a program connected.
- **Self-protection:** a guard that watches the tasks and the memory, a gate at the door of the panel when memory is short, and the confirmation of a new image once the node can be reached.
- **Firmware:** ESP-IDF 5.5 for the Waveshare ESP32-S3-ETH (W5500 Ethernet) and for an ESP32-S3-WROOM-1 (Wi-Fi); both images build without warnings. Nothing has run on a board yet.
- **Documentation:** the link protocol, the wiring of the RS-232 port, the lamps and the spindle's drive, and the design of the carrier board.
- Host tests of the link rules, the settings, the machine section and what every node shares, a check of the panel's texts in eight languages and of the tasks' stacks, in CI.

## [0.0.1] - First scaffolding of the node

- **Control link:** the frames of the link (CRC-16, a decoder that resynchronises after damage), the byte queue for the control unit and the rules of a control session (token login, arming, a stop when the session goes quiet or the connection drops), tested on a computer.
- **Spindle output:** a speed PWM for a 0-10 V converter (24000 rpm at full signal by default), run forward and reverse lines or one run and one direction line, a frame to set speed and direction, a stop with the machine, no direction change while turning or before the settling time, and the speed in the status and the panel.
- **Machine lamps:** HOME X, Y and Z, ENABLE and TOOL are read through a buffer transistor, shown in the status and on the panel, and a StopOnHome request drops the rest of a search as soon as an axis is home.
- **Machines:** the Bungard CCD MTC and CCD/2 MTC; the two ATC models are not covered.
